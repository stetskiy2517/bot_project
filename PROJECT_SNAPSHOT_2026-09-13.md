## 1. Текущее состояние продукта

Проект развивается как **web-first персональный секретарь**. Telegram оставлен как будущий дополнительный интерфейс, а не как основная платформа.

На текущий момент подтверждены и используются:

- Google OAuth;
- Google Calendar;
- календарь с естественными текстовыми и голосовыми командами;
- standalone-напоминания, не зависящие от Google Calendar;
- Web Push;
- заметки;
- второй экран «Сохранённое» с вкладками заметок и напоминаний;
- контекстная работа с открытой заметкой;
- свайп-действия над заметками и напоминаниями;
- долговременный журнал действий для будущего ИИ;
- PWA;
- CI/CD с автоматической выкладкой только после зелёных тестов.

ИИ в пользовательскую логику пока **не встроен**. Основная функциональность работает на обычном коде, правилах и парсерах.

## 2. Главные продуктовые решения

### Web-first

Основная версия — web/PWA. Telegram в дальнейшем должен использовать тот же router и бизнес-логику как дополнительный транспорт.

### Не всё через ИИ

Текущий принцип:

```text
обычная логика -> обычный код
понимание сложного контекста / анализ поведения -> будущий ИИ
```

### Tasks пока отложены

В репозитории остаётся старый код задач и тесты, но развитие отдельного Task-модуля сейчас **не является активным направлением**. Пользовательский фокус: календарь, напоминания, заметки, память и голосовой интерфейс.

### Удалить для пользователя ≠ уничтожить историю

Удалённые заметки и напоминания исчезают из пользовательского интерфейса, но их жизненный цикл сохраняется в отдельном журнале памяти для будущего ИИ.

Для настоящего физического удаления данных в дальнейшем нужен отдельный механизм приватности «Удалить навсегда».

- отдельный append-only журнал `ai_memory_events`;

- сам ИИ пока не подключён к журналу.

## 6. Голосовой интерфейс

Голосовая запись работает по удержанию:

```text
зажал -> запись
отпустил -> обработка
```

Добавлена отмена записи:

```text
зажал
 -> начал говорить
 -> не отпуская потянул палец вверх
 -> появляется корзина
 -> кнопка визуально тянется к корзине
 -> отпустил в зоне отмены
 -> аудио удаляется локально
 -> /api/voice не вызывается
```

Если палец не дошёл до зоны отмены, запись отправляется обычно.

Отмена работает для большой центральной кнопки и микрофона в чате.

## 7. Заметки

### Создание

Поддерживаются команды:

```text
Запиши заметку Проект Альфа: Иван ждёт смету
Список покупок. Бананы, масло, яйца
Проект Альфа. Иван ждёт смету
```

Заголовок хранится отдельно от тела.

Для обычных заметок без явного заголовка он выводится детерминированно.

### Контекст

После открытия заметки она становится активной.

Пример:

```text
Открыть «Список покупок»
Добавь воду
И молоко
Ещё яйца
```

Продолжения добавляются в открытую заметку.

### Работа со списком

Поддерживаются:

- просмотр всех заметок;
- поиск;
- открытие по названию;
- открытие по порядковому номеру последнего показанного списка;
- дополнение;
- удаление.

### Удаление

Свайп вправо по заметке -> `Удалить`.

Для пользователя заметка исчезает из списка и обычного поиска.

При этом физически история не теряется: событие удаления записывается в `ai_memory_events` вместе со снимком данных.

## 8. Standalone reminders

Напоминание — отдельная сущность, не календарное событие.

Пример:

```text
Каждый вечер в 11 напомни выпить таблетку
```

Разбор:

```text
тип: reminder
время: 23:00
повтор: ежедневно
текст: Выпить таблетку
```

Поддерживаются повторения:

- каждый день;
- каждое утро;
- каждый вечер;
- каждую ночь;
- по будням;
- по выходным;
- каждую неделю;
- по конкретному дню недели.

### Состояния

Пользовательский статус только один: **выполнено / не выполнено**.

Технический факт доставки push не показывается пользователю отдельным статусом.

Выполненное напоминание в списке просто аккуратно зачёркивается.

### Свайпы

По карточке напоминания:

```text
свайп влево
 -> Выполнено / Перенести
```

Если уже выполнено:

```text
свайп влево
 -> Вернуть / Перенести
```

```text
свайп вправо
 -> Удалить
```

Сам свайп не выполняет необратимое действие, а только открывает кнопку действия.

### Перенести

Быстрый выбор:

- `+1 час`;
- `Завтра`;
- `Выбрать` точную дату/время.

### Вернуть выполненное

Если напоминание ошибочно отмечено выполненным:

- `Вернуть` снимает статус;
- если исходное время ещё впереди — оно снова активно и сможет сработать;
- если время уже прошло — становится невыполненным, но старое уведомление повторно не отправляется.

### Удаление

После удаления напоминание исчезает для пользователя и больше не срабатывает.

История остаётся в памяти для будущего ИИ.

## 9. Web Push

Web Push работает в фоне и не требует открытого приложения.

Поддерживаются:

- несколько устройств пользователя;
- VAPID;
- сохранение подписок в SQLite;
- удаление истёкших подписок;
- повторная попытка при временной ошибке;
- Apple Declarative Web Push;
- Service Worker fallback;
- тестовый push из настроек.

### Push actions — состояние после PR #47

Напоминание теперь содержит действия:

- `Выполнено`;
- `Отложить`.

Обычный tap открывает приложение.

`Выполнено` приводит к выполнению конкретного reminder.

`Отложить` открывает тот же пользовательский выбор переноса, что используется после свайпа внутри приложения.

Для iOS добавлен deep-link/navigate путь, чтобы не полагаться только на `notificationclick` закрытого PWA.

Важно: внешний вид, положение кнопок и системные свайпы самого push контролируются iOS/Android, а не приложением.

## 11. Авторизация

Google OAuth остаётся основным входом.

После исправления постоянной сессии:

- cookie больше не browser-session only;
- срок web session — 90 дней;
- срок продлевается при использовании;
- `HttpOnly`;
- `SameSite=Lax`;
- `Secure` на HTTPS;
- обычный restart/deploy не должен разлогинивать пользователя;
- logout явно очищает session.

## 12. Память для будущего ИИ

На текущем этапе ИИ ещё не анализирует данные, но фундамент уже создаётся.

Журнал `ai_memory_events` хранит события вроде:

```text
created
updated
delivered
completed
reopened
rescheduled
deleted
```

Это позволит будущей модели видеть не только текущее состояние, но и **поведение пользователя во времени**.

Пример будущего сигнала:

```text
20:55 создано «Выпить таблетку»
21:00 доставлено
21:08 выполнено

повторяется много дней подряд
```

или:

```text
напоминание регулярно создаётся
но пользователь постоянно удаляет его
```

Такая информация должна использоваться позже для персонализации, предсказания потребностей и предложений действий.

### Важное ограничение приватности

Текущая кнопка `Удалить` означает «убрать из пользовательского рабочего пространства».

До коммерческого запуска необходимо добавить отдельный пользовательский механизм:

```text
Удалить навсегда
```

Он должен физически очищать рабочую запись и связанные записи памяти в соответствии с политикой хранения данных.

## 15. Что сейчас НЕ считать завершённым

### ИИ

Нет подключённого слоя, который:

- анализирует заметки;
- анализирует календарь;
- обучается привычкам;
- сам предлагает или создаёт напоминания;
- строит семантическую память;
- делает долгосрочные рекомендации.

Сейчас мы только собираем качественные структурированные данные для этого слоя.

### Tasks

Код старого task-модуля существует, но функциональность отложена и не должна расширяться без отдельного решения.

### Push UX на всех ОС

Логика push-actions реализована, но нужно живое тестирование на разных версиях iOS/Android/macOS/Chrome. ОС сама определяет способ показа action-кнопок.

### Полное удаление данных

Есть soft-delete для рабочего интерфейса, но отдельного пользовательского `Удалить навсегда` пока нет.
