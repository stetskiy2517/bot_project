## 1. Что подтверждено на момент снимка

- Web-first приложение работает онлайн по HTTPS.
- Google OAuth и Google Calendar интеграция работают.
- Production автоматически обновляется после зелёного CI через GitHub Actions.
- Основной runtime: Caddy -> Hypercorn -> Flask.
- Голосовой и текстовый ввод проходят через общий transport-neutral router.
- Голосовой ввод работает по удержанию кнопки: нажатие начинает запись, отпускание завершает и отправляет её.
- Случайные записи короче 400 мс отбрасываются до распознавания.
- UI объединён в один адаптивный экран: большая голосовая кнопка -> чат после команды -> возврат к основному экрану после бездействия.
- Календарные ответы сокращены и не показывают пользователю технический timezone `Europe/Moscow`.
- Отдельные напоминания больше не создаются как события Google Calendar.
- Web Push реализован для PWA/браузеров и после последнего исправления **подтверждён пользовательским тестом как рабочий**.
- Для Apple/WebKit используется Declarative Web Push; Service Worker остаётся fallback-механизмом.

## 3. Основные компоненты кода

### Web / PWA

- `web_app.py` — web entrypoint, API, auth session, push API, voice API.
- `web/index.html` — основной адаптивный UI.
- `web/reminders.js` — подписка на push, управление уведомлениями, клиентская логика напоминаний.
- `web/sw.js` — Service Worker, fallback Web Push и PWA cache.
- `web/manifest.webmanifest` — PWA manifest.

### Router / Planner

- `modules/router.py` — единая маршрутизация естественных команд.
- `modules/tasks.py` — отдельные задачи Planner.
- `modules/reminders.py` — отдельные напоминания.
- `modules/reminder_dispatcher.py` — фоновая доставка напоминаний через Web Push.

### Calendar

- `modules/calendar.py` — парсинг и создание событий.
- `modules/calendar_actions.py` — изменение, удаление и действия над событиями.
- `modules/calendar_availability.py` — свободные окна, ограничения по времени, конфликты и варианты.
- `modules/calendar_event_features.py` — место, участники, напоминания, приоритет и другие свойства.
- `modules/calendar_recurrence.py` — повторяющиеся события и scope операций.
- `modules/calendar_user.py` — чтение расписания и пользовательские запросы.
- `modules/settings.py` — рабочие часы, дни, буфер, категории и пользовательские настройки.

### Push

- `integrations/web_push.py` — VAPID, шифрование и отправка Web Push.
- `core/push_store.py` — постоянные push-подписки устройств.
- `modules/reminder_dispatcher.py` — отправка due reminders и тестовых push.
- Используется `pywebpush`.
- На современных Apple-платформах payload соответствует Declarative Web Push (`web_push: 8030`).

## 5. Отдельные задачи Planner

Задачи больше не подменяются календарными событиями.

Поддерживаются базовые сценарии:

- создать задачу;
- показать задачи;
- отметить задачу выполненной;
- удалить задачу.

Это отдельная сущность в SQLite и отдельный модуль `modules/tasks.py`.

Следующий этап для задач — расширять только после стабилизации календаря: дедлайны, фильтры, приоритеты задач, повторяемость и дальнейшая декомпозиция целей.

## 6. Напоминания

Напоминание — отдельная сущность, а не событие календаря.

Пример:

```text
Напомни в 10 вечера выпить таблетку
```

Результат:

```text
Standalone reminder -> SQLite -> background dispatcher -> Web Push -> устройство
```

Текущие возможности:

- создание напоминания естественной фразой;
- просмотр напоминаний;
- удаление напоминаний;
- доставка даже при закрытом web-приложении;
- несколько push-подписок одного пользователя;
- iPhone Home Screen PWA;
- desktop browsers;
- тестовый push из настроек;
- удаление истёкших подписок;
- повторная попытка при временных ошибках;
- VAPID key хранится вне Git;
- Declarative Web Push для Apple/WebKit;
- Service Worker fallback для совместимости.

## 11. Важный технический долг

Сейчас background reminder dispatcher запускается из web-приложения как daemon thread. Для текущего одноинстансового MVP это просто и достаточно.

При переходе к нескольким Hypercorn workers или нескольким инстансам приложения dispatcher нужно вынести в отдельный процесс/worker или добавить распределённый lock, иначе несколько процессов смогут одновременно пытаться доставлять напоминания.

Это **не блокирует текущий MVP**, но должно быть исправлено до масштабирования.

## 12. Зафиксированные продуктовые принципы

- Web-first.
- Telegram позже — только transport поверх общего router.
- Голос — универсальный ввод для всех модулей.
- Простую бизнес-логику не отдавать LLM без необходимости.
- AI нужен для понимания, анализа и сложного планирования, а не для каждого действия.
- Calendar, Tasks и Reminders должны оставаться разными сущностями.
- Ошибка необязательного модуля не должна останавливать приложение.
- Сначала стабилизировать Smart Planner, затем двигаться к следующим большим AI-модулям.
