## 2. Текущая схема MVP

```text
Пользователь / браузер
        |
        | HTTPS
        v
      Caddy
        |
        v
 Hypercorn + Flask
      web_app.py
        |
        v
  modules/router.py
        |
        +------------------------------+
        |                              |
        v                              v
AI Smart Planner / Calendar      другие модули позже
        |
        v
 Google Calendar API
```

Голосовой путь:

```text
Микрофон браузера
  -> MediaRecorder
  -> POST /api/voice
  -> integrations/speech.py
  -> AssemblyAI (русский язык, universal)
  -> нормализация распознанного текста
  -> общий router
  -> Calendar / Planner
```

Хранение состояния MVP:

```text
SQLite -> data/bot.db
```

## 3. Ключевые компоненты текущего кода

### Web

- `web_app.py` — основной web/PWA entrypoint и API.
- `web/` — мобильный web-интерфейс.
- Голосовой экран — основной интерфейс.
- Текстовый чат открывается свайпом влево.
- Настройки и аккаунт находятся в одном меню сверху справа.

### Router / Planner

- `modules/router.py` — центральная маршрутизация команд.
- `modules/calendar.py` — основной календарный модуль.
- `modules/calendar_actions.py` — действия с событиями.
- `modules/calendar_availability.py` — свободные интервалы и конфликты.
- `modules/calendar_event_features.py` — дополнительные свойства событий.
- `modules/calendar_user.py` — пользовательская логика календаря.
- `modules/settings.py` — настройки календаря.

### Auth / Google

- `modules/auth.py` — Google OAuth web flow.
- Пользователи и Google-токены изолированы по аккаунтам.
- В MVP календарь фактически интегрирован с Google Calendar.

### Voice

- `integrations/speech.py` — общий transport-neutral слой speech-to-text.
- Используется AssemblyAI.
- Голос из web и Telegram может идти через одну и ту же логику распознавания и router.

### Persistence

- `core/db.py` — SQLite и пользовательские данные.
- Production path: `data/bot.db`.
- `.env` хранится только на сервере и исключён из Git.

### Deployment

- `deploy.sh` — основной и рекомендуемый способ обновления/развёртывания MVP.
- Runtime: systemd + Hypercorn + Caddy.
- Docker для текущего production MVP **не используется**.

## 6. Что ещё не считается окончательно проверенным

1. Полный голосовой сценарий на iPhone/Safari: разрешение микрофона -> запись -> AssemblyAI -> router -> Calendar.
2. Beta-тест парсера реальными пользовательскими фразами, опечатками и разным стилем речи.
3. Поведение после реальной перезагрузки VM: systemd и Caddy должны подняться автоматически.
4. Длительная работа 24/7 и наблюдение за памятью/ошибками.
5. Резервное копирование `data/bot.db`.
6. PWA/cache/service worker на реальных мобильных устройствах.

## 9. Зафиксированные архитектурные принципы

- Web-first. Telegram позже — только один из transport-интерфейсов.
- Голос — универсальный вход для всех будущих модулей, а не часть календаря.
- Центральный router должен быть transport-neutral.
- Что можно надёжно сделать правилами — делаем без AI.
- AI подключается там, где он реально даёт дополнительную ценность.
- Модули изолированы: ошибка одного функционального блока не должна валить всё приложение.
- Перед расширением продукта сначала стабилизируем и beta-тестируем Smart Planner.
