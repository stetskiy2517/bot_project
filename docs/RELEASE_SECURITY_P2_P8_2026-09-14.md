## Реализовано

- Веб-вход привязан к начавшему его браузеру; одноразовое OAuth-состояние потребляется атомарно.
- Сессии отзываются на сервере. Старые сессии без серверного идентификатора требуют повторного входа.
- CSRF-защита изменяющих запросов и опроса напоминаний; запрет cross-site запросов, private/no-store для персонального API.
- Push: проверяемые ключи P-256, список допустимых провайдеров, запрет внутренних IP и перенаправлений, фиксированный IP соединения с проверкой исходного TLS-имени.
- Ключ запроса действует 24 часа и привязан к пользователю и содержимому. Один пользователь обрабатывается последовательно между потоками/процессами на одном сервере.
- После неизвестного результата запрос не запускается снова. Создание события Google сверяется по постоянному ID и маркеру запроса; остальные неизвестные исходы требуют проверки пользователем.
- Контекст уточнения хранится в SQLite до 30 минут, а не только в памяти процесса.

## Границы гарантий

Идемпотентность относится к одному и тому же ключу запроса в пределах срока действия. Два разных ключа с одинаковым текстом — две отдельные команды. Блокировка рассчитана на один Linux-сервер с общим SQLite/каталогом блокировок, не на несколько независимых ВМ.

При потере подтверждения не обещается абсолютное exactly-once для внешних сервисов. Безопасный вариант — не повторять неизвестную запись вслепую. Google-перенос/удаление при неизвестном результате не повторяются автоматически. Изменение календаря другим приложением между проверкой окна и записью полностью исключить нельзя.

Отмена не распространяется на Google Calendar, отправленные приглашения и удаление аккаунта. Просроченное или изменённое действие не восстанавливается поверх новых данных.

Принятие Push провайдером не означает показ или прочтение. Для прерванной отправки обзора остаётся статус неизвестного результата; она не повторяется автоматически после рестарта. Повторные уведомления и обзоры — не системный будильник.

Текстовый черновик имеет срок 24 часа; при недоступном localStorage остаётся только в памяти страницы. Аудио после закрытия/перезагрузки страницы пропадает. Сервер не хранит выгрузку; скачанный файл остаётся под контролем пользователя.

Штатный срок резервных копий — BACKUP_RETENTION_DAYS (по умолчанию 14 дней). Кнопка удаления не переписывает старые резервные копии и не удаляет копии, отдельно выгруженные администратором. При восстановлении старой копии требуется отдельно учитывать ранее удалённые аккаунты.

## Проверка и выпуск

Добавлены отрицательные тесты OAuth/CSRF/отзыва сессий, повторов и неизвестных исходов, изоляции пользователей, адресов Push/DNS/TLS, сохранения контекста, шаблонов, отмены, тихих часов, лимита повторов, экспорта и удаления.

Добавлены браузерные сценарии с реальным Flask API и временным SQLite. Внешние Google/ASR заменены тестовыми ответами; личные данные и production-секреты не используются. Реальные микрофоны, iOS/Safari, фоновая доставка Push и маршрутизация 2GIS должны проверяться на устройствах отдельно.

Перед выкладкой: общий набор Python, JavaScript/inline JS/shell, Chromium и проверка зависимостей. Скрипт обновления создаёт резервную копию до смены кода и после успешного запуска. Результаты окончательного CI и сведения о выкладке фиксируются в PR #56; локальные результаты не равны production-проверке.
